# Shared Character Movement

2026-09-07 기준 서버 `TimerThread()`의 이동 계산을
`Shared/Physics/CharacterMovement.h/.cpp`로 분리했습니다.
클라이언트와 서버 프로젝트 모두 해당 소스를 빌드하지만, 현재 호출부는 서버에만 연결되어 있습니다.

## 공동 작업 규칙

이 코드는 클라이언트 예측 이동과 서버 판정에 함께 사용됩니다. 로직을 추가하거나 변경할 때는 사전 회의에서 동작 방식을 정하고, 팀원 전원의 리뷰와 합의가 완료된 후에만 구현합니다.

## 책임

- Shared: 방향·대각선 계산, 캡슐 이동 차단 검사, 박스 윗면 선택, 중력·점프 적분 및 착지.
- Server: Session 입력·상태 변환, 지형 높이 조회, 정적 박스의 월드 좌표 변환, 틱 및 패킷 전송.
- Client: 이후 동일한 계산 함수에 예측 상태·입력·충돌 환경을 전달하는 연결 작업 필요

## 호출 계약

1. `CharacterMovementState`에 발 기준 위치(m), 수직 속도(m/s), 현재 점프 활성 상태를 담는다.
2. `CharacterMovementInput`에 yaw(rad)와 네 방향 입력을 담는다. yaw는 호출자가 이미 계산한 최종 방향(비조준 시 이동 방향, 조준 시 카메라 방향)이며, 네 방향 입력은 방향 계산에는 쓰이지 않고 "이동 중인지" 여부를 가리는 게이트로만 쓰인다.
3. 이동 전 위치의 지형 높이와 월드 좌표의 박스 목록을 준비해야 한다.
4. `StepCharacterHorizontalMovement()`에 충돌 월드, 본인 ID, 이동 속도와 고정 dt를 전달한다.
5. 반환한 바닥 높이를 `StepCharacterVerticalMovement()`에 전달한다. (이때, 중력 인수는 양수 크기)

호출자는 유효한 입력과 양수 고정 dt를 제공하고, 계산 중 충돌 월드 및 상태의 동시 수정을 관리해야 합니다.

## 유지한 동작과 범위

- 서버의 0.05초 dt, 5m/s 이동, 기존 `GRAVITY`를 유지합니다.
- 수평 이동 반영 → 위치 전송 → 수직 이동 계산 순서를 유지합니다.
- 지형 높이는 이동 전 x/z에서, 박스 윗면은 이동 후보 x/z에서 조회하는 기존 규칙을 유지합니다.
- 이동이 차단되어도 후보 위치에서 선택한 바닥 높이를 사용하는 기존 동작을 유지합니다.
- 점프 중이 아니면 바닥 높이로 맞춥니다. `isJumping`은 실제 접지 검사의 결과가 아닙니다.
- 점프 요청의 승인과 `JUMP_POWER` 적용은 기존 `PacketHandler::HandleJump()`에 남아 있습니다.
- 서버는 타이머 시작 시 정적 집 박스를 월드 좌표로 변환합니다.

클라이언트 예측에 연결할 때는 양쪽의 시간 간격, 지형·충돌 데이터와 이동 설정을 맞춰야 합니다.
예측 입력 기록·재실행, 서버 확인 번호 및 화면 보정은 별도 작업입니다.
