LOD는 같은 UV와 텍스처 세트를 공유한다. DDS와 밉맵은 만들지 않았으므로 사용자가 엔진에 맞게 변환하면 된다. 밉맵은 텍스처의 축소 단계이고, LOD는 메시의 축소 단계다.

Base Color·Emissive만 sRGB로 읽고 나머지는 선형 데이터로 읽는다. 노멀 맵 사용 시 셰이더에서 RGB를 [-1,1]로 복원하고 정규화한다. `Normal_DX` 사용 여부는 엔진의 탄젠트/바이탄젠트(TBN) 규약과 맞춰야 한다. DirectX API 자체가 녹색 채널 반전을 강제하는 것은 아니다.

## 현재 프로젝트 OBJ 경로에 적용

현재 로더가 OBJ의 Z를 반전하고 삼각형 정점 순서를 뒤집는 경로에 맞췄다.

1. `obj_dx/`의 OBJ를 사용한다.
2. 로더의 기존 Z 반전과 삼각형 순서 반전은 유지한다.
3. OBJ의 V는 이미 `1-v`로 변환했다. 로더나 DDS 변환에서 V 또는 이미지 상하를 다시 뒤집지 않는다.
4. `map_Kd`는 `../textures/P02_BaseColor.png`를 가리킨다. OBJ 로더가 MTL을 읽지 않으면 동일한 Base Color DDS를 직접 연결한다.
5. FBX는 Blender 기본 UV와 일반적인 RH +Y 위/-Z 정면 좌표를 사용한다. OBJ와 동일한 사전 V 반전 규칙을 적용한 파일이 아니다.

LOD 파일을 만들었다고 게임에서 자동 전환되지는 않는다. 엔진이 거리나 화면 점유율에 따라 하나만 선택해서 그려야 한다.

`skinned_dx` JSON은 이미 LH +Y 위/+Z 정면 좌표와 V 반전을 적용한 데이터다. 추가 좌표·UV 변환을 하지 않는다. 본 행렬은 행별 배열에 저장했지만 계산은 열 벡터 규약이다. DirectXMath의 행 벡터 곱을 쓰면 행렬을 전치한다. 애니메이션 JSON은 최종 스킨 행렬이므로 역바인드 행렬을 다시 곱하지 않는다.

## 충돌

```
box P02_Player 0.000000 0.930000 0.000000 0.300000 0.930000 0.230000 0.000000 0.000000 0.000000
```

중심은 `(0,0.93,0)`, 반길이는 `(0.30,0.93,0.23)`m이다. 전체 크기는 0.60 × 1.86 × 0.46m다. 플레이어 이동용 고정 상자이며 A 포즈의 펼친 팔을 포함하지 않는다. 총알 판정용 부위별 히트박스나 애니메이션에 따라 변하는 충돌체는 아니다.

## 리그와 검증 범위

자체 32개 본, 정점당 최대 4개 영향, Idle·Walk·Run·Aim·Interact·Down 미리보기 6개다. Aim과 Down은 자세 확인용 정적 클립이다. 손가락의 정밀한 관절 구조, 장갑의 강체 변형과 어깨·골반의 변형은 실제 사용할 애니메이션에 맞춘 추가 조정이 필요하다. 얼굴 블렌드셰이프, IK 컨트롤 리그, Epic 리타게팅, 무기, 분리된 9개 의상 파츠는 포함하지 않는다.

OBJ 재임포트, 삼각형 수, UV, 노멀, 퇴화 면, FBX 재임포트 시 본·동작·가중치 유지, Blender 변형과 DX 스킨 행렬 계산 결과의 일치를 검사했다. 실제 졸업작품 엔진에서 렌더링하거나 애니메이션을 재생한 검증은 아직 하지 않았다.

출처와 평가 생성물의 이용 범위는 [LICENSE_NOTES_KO.md](LICENSE_NOTES_KO.md)에 기록했다. 상용 제품의 모든 기능과 완성도를 동일하게 제공하는 것으로 표시하지 않는다.
